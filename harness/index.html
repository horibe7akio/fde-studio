3Dでわかる / ハーネス

同じ選手でも、
ボードで結果が変わる。

同じ選手が、ある試合では勝ち、別の試合では負けます。何が違うのでしょう。サッカーの試合で見ていきます。

SCROLL

01 / 選手と、クラブと、ボード

選手は答えるだけ。
クラブが手足になる。

選手＝AIのモデル（Claude Opus 5.5 など）。できるのは、次に何をするかを文字で答えることだけです。自分ではファイルも開けず、コマンドも打てません。

クラブとスタジアム＝公式のハーネス（Claude Code そのもの）。選手が「このファイルを読みたい」と言ったら、本当に読んで結果を返す。ファイルの編集、コマンド、ウェブ検索などの道具を用意し、毎回選手に何を見せるかを決め、長くなったら要約して詰め、「実行してよいか」で止める。作っているのは Anthropic で、v2.1.283 のように頻繁に更新されています。

作戦ボード＝監督が書く設定（CLAUDE.md、メモリ、スキル、フックの中身）。クラブが、試合の前に選手へ渡してくれる紙です。

02 / 最大公倍数

攻撃的にしようとして、8-1-1。

どの試合でも勝てるように、ボードに書き足していく。気づけば、最大公倍数。

燃費がよくて、速い車のようなハーネスは幻想。

公式の目安は、CLAUDE.md 1ファイルにつき200行以内。長いほど守られにくくなり、矛盾するルールはどちらかを勝手に選ぶことがある、とあります。

03 / 仕組み

ボードの線が、
選手の動きになる。

ボードに書いた線は、そのまま選手の動きになります。確認しろと書けば止まり、止まるなと書けば走る。

公式にも、CLAUDE.md は強制ではなく文脈として扱われるので、必ず止めたいときはフックを使うように、とあります。

04 / 相手が違えば

相手が違えば、
勝てる並びも違う。

ミスが許されないアプリ開発には、5-4-1。速さが勝負のゲーム制作には、4-3-3。

05 / ボードを分ける

ボードを、
試合ごとに分ける。

ボードを試合ごとに分けると、両方とも勝てる。

とある案件（試合）で最適なハーネスは、他の試合で最適とはかぎらない。

06 / 毎日

だから監督は、毎日ボードを書き直す。

明日は、相手が変わります。スタジアムも、更新で変わっていく。
